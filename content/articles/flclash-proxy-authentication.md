FlClash 开启“认证”后，一些手动设置代理的应用突然不能连接，先检查应用是否提供了本地代理账号。这个账号不是你的订阅账号，也不是节点 UUID。本文依据 FlClash v0.8.99 通用配置页面与 mihomo 官方端口说明。

## 将地址、端口和两种凭据分开

| 项目 | 作用 |
| --- | --- |
| 本地代理地址与端口 | 应用连接到客户端的入口 |
| 本地代理认证账号 | 验证连接本地代理的应用 |
| 远端节点认证 | 客户端与服务器建立连接所需的参数 |
| 订阅地址 | 获取配置，通常包含独立的访问授权 |

FlClash 的[通用配置源码](https://github.com/chen08209/FlClash/blob/68c71b8ef9b7486a224972eb371ff153c6b2de0f/lib/views/config/general.dart)读取 mixedPort，并提供认证开关、账号和密码字段。mihomo 的[混合端口文档](https://wiki.metacubex.one/config/inbound/port/)说明该端口接受 HTTP 与 SOCKS 代理协议。不要把内核控制接口地址填到应用的 HTTP 代理栏里。

## 先在本机核对真实设置

不要默认端口永远是 7890；先读当前页面的值。确认应用填写的协议与入口一致，地址指向实际运行 FlClash 的设备。测试同一设备时使用本机地址，不需要把代理开放到局域网或公网。

首次打开认证时，源码会在账号为空的情况下生成账号与密码。因此只记得点过开关，却继续在应用里使用空账号，可能与实际设置不一致。以你自己的配置页为准，不把示例账号复制当成真实账号。

## 最小对照应包括哪些信息

保存认证前的状态，选取一个支持代理认证的应用。先确认客户端服务运行，再输入当前端口和本地认证信息，访问一个授权目标。记录的是错误阶段与状态，不是账号明文。

若应用报告认证失败，重新核对账号字段、是否保存以及应用是否支持该认证方式。固定版本账号输入会移除冒号并整理首尾空白；不要通过在用户名中加入“账号:密码”来替代两个字段。密码应由应用提供的独立密码输入项处理。

| 观察 | 更值得先查的环节 |
| --- | --- |
| 连接被拒绝 | 端口、监听和服务状态 |
| 代理认证失败或 HTTP 407 | 应用有没有提交正确的本地代理凭据 |
| 认证通过后目标仍失败 | 再检查路由、出口和目标错误 |
| 只有某个应用失败 | 核对该应用的代理协议与认证能力 |

## 系统代理也要单独验收

[网络设置源码](https://github.com/chen08209/FlClash/blob/68c71b8ef9b7486a224972eb371ff153c6b2de0f/lib/views/config/network.dart)会在启用认证时给 Android 的 VPN 系统代理设置显示相关说明。不同应用处理代理认证的能力不同，系统代理开关变化并不保证所有应用都自动获得账号。

测试失败后，先恢复原有应用代理设置和客户端认证状态，再确认原路径恢复。若原本需要认证保护，不应为了方便而长期取消认证；可以停止相关代理入口，待确认应用支持方式后再启用。

## 核验记录与边界

2026-10-04 核对上述 v0.8.99 页面源码和 mihomo 官方混合端口说明。没有读取你的密码，也未进行应用认证实测。不要把账号、密码或整份配置放进公开反馈；错误类型、端口代号和前后开关状态已足够开始定位。
