## 先把一台设备用通

FlClash 的开发者 README 说明了多平台、订阅链接和 WebDAV 同步能力。首次使用时，建议先在一台设备完成配置与连接验证，再启用同步；否则分不清是原始配置异常，还是同步覆盖带来的变化。

准备客户端版本、系统与架构、服务方提供的适配订阅、一个固定测试地址。下载阶段可以先阅读本站有实际校验记录的[安装包选择教程](/articles/flclash-package-guide/)。本文不假定所有版本使用相同按钮文字。

## 1. 导入后检查实际使用对象

以 v0.8.98 的添加配置源码为准，在“配置”中选择“添加配置”，可见二维码、文件、URL 三种入口。订阅地址选 URL，在导入对话框粘贴完整链接；它会检查空值和 URL 格式，但通过输入检查不代表服务器内容有效。导入后再更新并核对结果。检查更新结果，选择该配置作为当前使用项，再选择代理组的实际出口。不要只看首页启动按钮：启动核心和加载正确配置是两个条件。

若更新报错，先保留第一条错误。下载失败看地址与网络；解析失败看格式与核心支持；导入后数量变化看服务方更新和筛选设置。不要把私有订阅交给不可信的公共转换服务，也不要靠改文件后缀解决格式问题。

## 2. 分平台验收接管

桌面系统代理路径：确认系统设置中本地地址与 FlClash 显示的端口相同，使用固定浏览器新建请求。Android 路径：确认 VPN 授权与状态，并检查其他 VPN 是否占用。Linux 路径：区分程序启动依赖与网络接管问题，窗口打不开时先看启动错误，不先更改节点。

同一配置在两台设备结果不同，先记录平台、客户端版本和内核信息。不要假设同名配置已经带上了所有系统权限、VPN 授权或应用专属代理设置。

## 3. 一次请求保留三项结果

记录目标、时间和实际出口。页面成功还应能与客户端连接记录对应；连接记录使用 DIRECT 可能是规则正常直连，不必仅凭该字样判定失败。若测试时使用自动策略，记录当时真正选中的节点。

| 结果 | 应查方向 |
| --- | --- |
| 页面失败且没有对应记录 | 应用入口、系统代理、VPN 或日志范围 |
| 有记录但命中意外出口 | 当前配置、策略组与规则顺序 |
| 有记录且连接远端失败 | 具体错误、节点参数与网络路径 |
| 浏览器正常而其他应用失败 | 应用是否支持或遵循同一种接管方式 |

## 4. 同步前先防止覆盖误判

在每台设备分别保留本地备份，确认 WebDAV 服务的地址、账户和目标目录属于你可控制的位置。首次同步时先读清软件当前操作是上传、下载还是合并；若界面含义不明，先停下来查对应版本说明，不拿唯一配置试验。

同步后检查配置数量、当前选中项、策略选项，并在目标设备重新完成接管验收。数据到达不等于 VPN 权限或系统代理已配置。同步故障与代理链路故障应分开记录。

## 回退和证据边界

新配置失败时恢复先前可用配置与接管状态，再使用同一测试请求比较。反馈保留版本、同步方向、发生时间与脱敏日志，不提供完整订阅或 WebDAV 密码。

[FlClash 开发者说明](https://github.com/chen08209/FlClash)是功能范围来源，[v0.8.98 发行页](https://github.com/chen08209/FlClash/releases/tag/v0.8.98)是本次版本基线。2026-09-19 已实际下载并校验 Windows ZIP；未运行 GUI、真实订阅或 WebDAV 服务。因此本篇是原创验收流程，不能称为同步和连接均已亲测。
